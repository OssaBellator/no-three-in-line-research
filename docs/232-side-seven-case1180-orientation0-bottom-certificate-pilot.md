# Explicit bottom-infeasibility certificate pilot for side-seven case 1180

PX739--PX742 close multiplicity-four global cases `1180` through `1279` by the shared exact CSP. This chapter develops a narrower proof-object route for one fixed clean top order.

This is a certificate-format pilot, not a proof of the entire shard and not an infinite product theorem.

## 1. Certified fixed-top statement

### Theorem PX743 -- PROVED FINITE

Take global multiplicity-four case `1180`, radix orientation `0`, and the lexicographically first clean concatenated top assignment generated by `TopEnumerator`:

`0,1,3,2,5,4,6,0,3,1,2,6,5,4`.

For every one of the `7! = 5,040` bottom-row permutations and every one of the four selectors in the case, the resulting 28-point set contains an explicitly recorded integer-collinear triple. Thus none of the four selectors extends this fixed top order to a no-three embedding.

The statement consists of

\[
5{,}040\cdot4=\boxed{20{,}160}
\]

independently checkable selector-permutation obligations.

## 2. Binary proof object and checker

### Theorem PX744 -- PROVED FINITE CERTIFICATE

`scripts/verify_product_side_seven_case1180_orientation0_bottom_certificate.cpp` deterministically generates a binary certificate with:

- a 56-byte header recording the case, orientation, fixed top assignment, candidate count, permutation count, and transcript digest;
- one three-byte row-major edge triple for each of the 20,160 obligations;
- total size `60,536` bytes;
- transcript digest `16630590496048926721`.

The checker regenerates the exact radius-three selector layer and the specified first clean top assignment, but it does **not** invoke `BottomGroupSolver`. For each certificate record it checks that all three edges belong to the stated selector and that their exact integer determinant is zero under the stated bottom permutation. It also verifies the file length and transcript digest.

This separates search from checking: the generated proof object can be validated by a direct linear pass over explicit geometric obstructions.

## 4. Next proof-producing step

The immediate extension is to generate one certificate per clean top order, then replace repeated explicit triples by a dictionary and extract top-assignment cores shared by many orders. That route can support master nogoods and, eventually, a proof-logged selector-choice encoding.
