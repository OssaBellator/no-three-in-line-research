# Closure-envelope rematches are exactly internal or strict ancestor expansions

This chapter records CMR2994--CMR3007. CMR172--CMR175 define the canonical
closure envelope from the union of moved columns and prove row-set invariance.
CMR193--CMR195 show that moving any point of a crossing target forces strict
envelope expansion. The present chapter turns those statements into a sealed
transition system.

The executable checker is:

```text
scripts/check_prime_power_closure_envelope_transition_ancestry.py
```

## CMR2994 — canonical closure-envelope identity

For ambient side `n=p^h` and a nonempty moved-column history `Y`, the checker
recomputes the largest depth `s` for which all columns of `Y` have the same
residue modulo `p^s`. It records the exact prefix block

\[
C_{s,a}
=
\{x: x\equiv a\pmod{p^s}\},
\]

its depth, residue, column set, block side and SHA-256 identity.

## CMR2995 — inherited two-layer row sets

A legal closure move rematches selected columns in one permutation layer to the
same selected row multiset. For the canonical envelope and every later ancestor,
the checker verifies that both current layer row sets agree exactly with the row
sets of the initial branch state.

This is the executable CMR172 invariant.

## CMR2996 — exact row-preserving rematch transition

Every record contains the initial, parent and child saturated two-layer states,
the complete parent and child moved-column histories, the selected layer,
selected columns and new selected rows. The child state is regenerated by the
literal row-preserving rematch and checked for saturation and layer disjointness.

## CMR2997 — internal-envelope transition

If every selected column belongs to the current envelope, adding those columns
to the moved history cannot change its least containing prefix block. The typed
operation

```text
transition_kind = closure-envelope-internal-rematch
```

therefore has equal parent and child envelopes and one unchanged envelope-owner
label.

## CMR2998 — strict-envelope expansion transition

If at least one selected column lies outside the current envelope, the moved
history has a strictly shorter common lower-digit prefix. The typed operation

```text
transition_kind = closure-envelope-strict-expansion
```

satisfies

\[
d(E_{j+1})<d(E_j),
\qquad
E_j\subsetneq E_{j+1}.
\]

The theorem-derived envelope-owner label changes exactly in this branch.

## CMR2999 — exact envelope-owner identity

The envelope owner is the digest of:

```text
operation type = closure-envelope epoch
canonical envelope identity
inherited layer-zero row set
inherited layer-one row set
```

Internal rematches preserve this owner. Strict expansions produce the exact
ancestor-envelope owner with the inherited row sets over that ancestor.

## CMR3000 — crossing-target destruction ancestry

For a current collinear target with a point outside the envelope, the checker
selects an outside point, generates a legal four-endpoint rematch in its layer,
and verifies simultaneously that:

1. the outside point's old cell is removed;
2. the target is destroyed;
3. saturation and layer disjointness survive; and
4. the child envelope is a strict ancestor.

This is a literal CMR193 transition rather than a scale-only witness.

## CMR3001 — nested depth chain

Envelope depths are nonincreasing integers in `[0,h]`. Every strict expansion
decreases depth, so one branch has at most `h` strict expansions and at most
`h+1` envelope epochs.

The checker constructs the exact binary side-eight chain

```text
3 -> 2 -> 1 -> 0
```

with a distinct theorem-derived owner at every strict expansion.

## CMR3002 — canonical epoch parent assignment

All internal rematches before the next strict expansion share one envelope owner.
The resulting owners form a nested prefix chain. This is the executable CMR175
parent assignment.

## CMR3003 — exhaustive closure-rematch partition

```text

selected columns include an outside column
```

Hence the internal and strict-expansion kinds are pairwise disjoint and exhaustive
for closure-branch rematches.
